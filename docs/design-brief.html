What is actually true today

This brief separates what has been executed from what is designed. Every claim below marked runs was run in this session against the tree at commit ce28bad (PR #1, merged). Where this brief once described a defect, it now describes the fix and links the commit that made it.

All four verdicts run, with no model, no camera and no AWS. Four scripted scenarios drive the pan; each verdict is reachable in about two seconds via /dev/control or ?name=steam&at=40. Verified live over HTTP and through a real MCP client at protocol 2025-11-25. Captured as docs/demo/mvp-verification.mp4 and five panel screenshots — including the two the repo never had, panel-refuse.png and panel-abort.png.
A clean clone installs and imports. mcp is capped below 2.0: an uncapped >=1.27 resolved to 2.2.0, where mcp.server.fastmcp no longer exists. Seven test suites pass. The AWS layers are declared as a [aws] extra rather than silently absent.
Still not executed: the model itself. BedrockVision.judge is written against a call shape verified in botocore's own service model, but has never run — blocked on an unsubmitted Anthropic use-case form and an IAM grant, neither of which is code. Policies are ready in infra/. Nothing is deployed to AWS.
Five contract bugs found and fixed, each with a regression test. Rule 2's cooldown was keyed on step rather than verdict, so a plain wait silenced a genuine refuse and the voice spoke a readiness claim about a frame it had just declined to read. Rule 4 promised to hand control back and never did. STORE.write() stamped the write rather than the shutter, so a 2-3 s vision call would have read as freshness. Calibration was resolved by mutating a shared Step, so the panel showed a stale gate. And the scripted pan kept writing at 1 Hz alongside the camera — point a phone at a real hob and the panel would have shown the simulated one.
The load-bearing decision

Two planes, joined by one cache

Alexa+ budgets roughly 500 ms per tool round-trip. A vision model does not fit in that budget and never will. So the system is split in two, and the split is what makes a genuinely agentic design possible instead of impossible.

The slow plane is a Strands multi-agent graph running on its own clock at about 0.3 Hz. It reasons, argues with itself, and writes a last-known-good CookState. The fast plane is the MCP tool surface: it reads that cache and applies a deterministic threshold. No model is ever called inside a tool.

This is why "is the agent real?" has a good answer here. The agent is real and it is complex — it simply does not sit in the request path. Putting it there would not make the product more agentic; it would make it time out.

"Can I add the garlic yet?"

The sequence below is the demo, and it deliberately shows the refusal path rather than the happy one. Doneness reads 0.88 against a 0.80 gate — a naive system says GO. A bug this sequence exposes, and it is in the shipped code. Policy rule 2 suppresses a repeated refusal within 120 s, but the cooldown is keyed on step, not on verdict, and the suppressed string is "Still not yet." — a wait phrasing. So a normal wait at t=0 will silence a genuine refuse at t=30 s and speak a confident readiness claim from a frame the system just decided it could not read. Proven live this session. It is the one defect that defeats the project's own thesis, and it is a five-line fix.
Agent topology

Five agents across two Strands graphs

Yes, this is genuinely multi-agent, and yes, there is real agentic reasoning — but only where a separate agent earns its place. The test applied to every node: does it have a distinct trigger, a distinct model tier, or a distinct failure domain? If not, it is a function wearing a costume, and a judge will say so.

The graph, in Strands

GraphBuilder gives deterministic execution order with conditional edge traversal — which is exactly what the critic needs, and why a Graph beats a Swarm here. Autonomous handoff would make cost and latency unpredictable on a loop that runs every three seconds. 

# src/mise/agents/hot.py — the per-frame graph
from strands import Agent
from strands.multiagent import GraphBuilder

perception = Agent(name="perception", model="au.anthropic.claude-haiku-4-5", ...)
critic     = Agent(name="critic",     model="au.anthropic.claude-haiku-4-5", ...)
risk       = Agent(name="risk",       model="au.anthropic.claude-haiku-4-5", ...)

def near_the_gate(state) -> bool:
    """Only pay for a critic where a mistake is expensive."""
    r = state.results["perceive"].result
    return r.confidence < 0.75 or abs(r.doneness - r.gate) < 0.1

b = GraphBuilder()
b.add_node(perception, "perceive")
b.add_node(critic,     "critique")
b.add_node(risk,       "risk")
b.add_node(arbiter,    "arbitrate")        # custom node, no model
b.add_edge("perceive", "critique", condition=near_the_gate)
b.add_edge("perceive", "risk")
b.add_edge("perceive", "arbitrate")
b.add_edge("critique", "arbitrate")
b.add_edge("risk",     "arbitrate")
b.set_entry_point("perceive")
b.set_execution_timeout(20)              # drop the tick, never queue it
HOT = b.build()
Verify before building. GraphBuilder, add_node, add_edge, set_entry_point and set_execution_timeout are confirmed in the Strands docs, as is conditional edge traversal. The exact condition= signature and the shape of state.results were not verified in this session — check them against the installed version first.
The mini challenge that pays $5,000 + $5,000

AgentCore, service by service

The AWS Builder rule asks for documented integrations. That means each service must be named with a reason: what primitive, and why that primitive rather than a simpler one. Six services carry real weight here. The seventh is named and declined, on purpose — volunteering what you did not need reads as judgement, not as a gap.

Runtime — two deployments, not one

Runtime hosts MCP servers natively. The service expects the container at 0.0.0.0:8000/mcp, which is the default path for the official SDKs, and it adds an Mcp-Session-Id header automatically to any request that lacks one, so clients keep continuity to the same runtime session. Stateless mode (stateless_http=True) is the recommended default.

src/mise/server.py already matches this contract exactly — FastMCP(..., stateless_http=True, json_response=True). That is a genuine piece of luck worth keeping: the existing server is already Runtime-shaped. 

# Deployment A — the MCP server (the fast plane)
npm install -g @aws/agentcore

agentcore create --project-name mise --no-agent
agentcore add agent \
  --name MiseMCP \
  --language Python \
  --protocol MCP \
  --authorizer-type CUSTOM_JWT \
  --discovery-url "https://cognito-idp.ap-southeast-2.amazonaws.com/$POOL_ID/.well-known/openid-configuration" \
  --allowed-clients "$CLIENT_ID" \
  --request-header-allowlist Authorization
agentcore deploy

# -> arn:aws:bedrock-agentcore:ap-southeast-2:ACCT:runtime/MiseMCP-xxxxxx

The second deployment is the agent graph, on the same Runtime but with the default protocol rather than MCP. It is a long-running loop, not a request handler, and it writes to the shared cache. Keeping them as separate runtimes is the whole architecture expressed in deployment: the slow plane can crash and restart without taking the voice path with it.

Decide early: where does the cache live? Today state.STORE is an in-process dict, which only works while both planes share a process. Two Runtimes means two processes. Either co-locate them in one container for the demo (simplest, and honest), or move the cache to a small store. Do not discover this on demo night.

Memory — the half nobody else does

Samsung and GE calibrate to the appliance they sold you. Nothing calibrates to your burner, your pan, and what you mean by translucent. The long-term userPreferenceMemoryStrategy is exactly the right primitive: it is durable across sessions, namespaced per actor, and the demo moment is a visible behaviour change between session 1 and session 3. 

from bedrock_agentcore.memory import MemoryClient

client = MemoryClient(region_name="ap-southeast-2")
mem = client.create_or_get_memory(
    name="mise-cook-calibration",
    strategies=[{"userPreferenceMemoryStrategy": {
        "name": "doneness-preferences",
        "namespaces": ["cook/{actorId}/hob/"],   # trailing slash REQUIRED
    }}],
)
  • Namespaces must end in a trailing slash — otherwise multi-tenant prefixes collide.
  • Watch the size limits. IngestData writes arbitrary JSON straight to long-term memory but caps at 100 KB per item and per request. CreateEvent allows 10 MB. Frames go nowhere near either.
  • Keep the local JSON fallback. The project must still run on a laptop with no credentials — check CALIBRATION.backend to see which path is live.

Policy — Dogwood is the reason the gate is a contract

Dogwood is a strict superset of Cedar that adds formerly within, since within, count and sum. That matters because it lets a decision condition on what the agent has already done in this session, scoped by the x-amzn-bedrock-agentcore-policy-session-id header. A model cannot talk its way past a policy that reasons over its own action history. 

// 1. Advancing requires a passing gate OBSERVED in the last 20 seconds —
//    not "the model believes it is ready".
permit (principal, action == Action::"advance_step", resource)
when { context.gate_passed formerly within 20 seconds };

// 2. Alarm fatigue. A coach that repeats itself gets muted,
//    and a muted coach cannot warn you when it matters.
forbid (principal, action == Action::"speak_refusal", resource)
when { count(context.refusals_for_step) >= 1 since within 120 seconds };

// 3. Danger is never rate-limited and never confidence-gated.
permit (principal, action == Action::"speak_abort", resource);

// 4. Three corrections on one step means the threshold is wrong,
//    not the cook. Stop gating and hand control back.
forbid (principal, action == Action::"block_advance", resource)
when { count(context.corrections_for_step) >= 3 since within 3600 seconds };
Claim this carefully until it is deployed. policies/mise.dogwood has never been evaluated by AgentCore Policy in this project; policy.py mirrors the semantics locally. Until the ARN exists, describe it as "the policy expressed in Dogwood, evaluated locally" — that sentence costs nothing and removes the single most likely interrogation question.

Identity, Observability, Evaluations

  • Identity — inbound OAuth on the Runtime (Cognito user pool, CUSTOM_JWT). It also supplies the stable actorId that Memory's namespace is keyed on, so it is load-bearing rather than ceremonial. Note: missing auth returns 401 with a WWW-Authenticate header pointing at the protected-resource metadata.
  • Observability — traces every node in the hot graph. This is the cheapest judge-visible evidence in the whole build: a trace waterfall showing the critic firing on 1 tick in 12 proves the conditional edge is real rather than decorative.
  • Evaluations — where evals/abstention.py lands as a custom evaluator, scored over recorded pan footage.

Gateway — named and declined

Gateway federates external APIs into MCP tools. Mise has no external API to federate: the recipes are local and the camera is local. Forcing it in would add a hop and a dependency for a line on a slide. Say this out loud in the submission.

Bedrock and the region choice

Deploy in ap-southeast-2, where AgentCore is GA for Runtime, Memory, Gateway, Identity, Policy, Evaluations and Observability. Sydney has no apac. Anthropic profile, so the real choice is:

  • au.* — cross-region Sydney↔Melbourne, data residency, 4.5-generation models.
  • global.* — frontier models, no residency guarantee.

Take au.*. For a device with a camera in someone's kitchen, "the frames never leave Australia" is a product decision with a reason, and it scores under Design and Potential Impact rather than just Tech. It is also a real trade — say which models you gave up.

Used — Amazon's own MCP server

There is no Alexa-provided MCP server to consume; Alexa+ is the host, not a server. But the resources page ships Amazon Devices Builder Tools, an MCP server for AI coding assistants offering documentation search and guided workflows. Wire it into this session's coding assistant and use it. Two reasons, both worth points: it is a tool "used in your project," which the mandatory product-feedback requirement then covers, and it will generate friction-log entries on contact.

Two feedback artefacts, not one. docs/FRICTION.md is the optional friction log worth up to a 10% bonus. Separately, the rules make Product Feedback mandatory for each tool, API or SDK used, answering five named questions: what you used it for, what worked well, what needs work, how onboarding felt, and whether you would build with it again. That artefact does not exist yet. Also note four of the six banked friction entries are about Ring and Vega — tracks not used here. They are legitimate friction, but they do not discharge the mandatory requirement.
Sequenced, because the order is load-bearing

Build order

Roughly 37 days, solo, evenings — call it 85 to 100 usable hours with 12 reserved for the video and the writeup. The ordering is not preference. Phase 01 comes first because the differentiating verdict has never once appeared on screen, and without it there is no demo to shoot no matter how the rest goes.

  1. doneAll four verdicts reachable ScenarioSource replaced the simulator, which hardcoded confidence=0.88 and risk="none" and pinned the pan at 1.0 after forty-five seconds. Four scenarios, deterministic, restartable, seekable. Frames carry their own age, so staleness lands in one tick instead of fifteen seconds of motionless screen.
  2. doneThe refusal contract holds Cooldowns keyed per verdict; rule 4 wired into the ledger where all three enforcement layers read it, with danger excluded at both ends and a risk != "urgent" guard added to the Dogwood rule — forbid beats permit, so without it rule 4 would have forbidden blocking an advance over a burning pan.
  3. donePublic repo, licence, clean install jwlai-cloud/mise, Apache-2.0 detected by GitHub, copyright holder named. mcp<2 pinned.
  4. doneDocs corrected where they overstated PROGRESS.md's "verified end to end" corrected in place; the three-layer table now says which layers run; the abstention figure relabelled as the smoke test it is.
  5. doneThe abstention metric rewards calibration, not luck It judged a refusal by whether a noisy estimate happened to land on the right side of the gate, scoring the steamed-lens and blocked-pan frames — the product's whole point — as mistakes. Now judged on |doneness − label_doneness| > 0.15, with a risk-coverage sweep. That sweep reversed the plan: there is a safe plateau from 0.35 to 0.85 and the current floor was never the problem.
  6. doneThe real-frame path, behind a seam perception.py is the only place a model runs. Confidence is clamped in code to what the model admitted it could see, and can only ever fall. A failed call writes nothing — silence is how the system refuses.
  7. yours · blocks everythingThe Anthropic use-case form and the IAM grant The form gates every model call in every region and surfaces as ResourceNotFoundException, not an auth error. infra/deployer-policy.json and the mise-runtime execution role need an admin principal — the CLI user cannot self-grant.
  8. 3 evenings, hard capThe vision spike Three real cooks, fixed camera, a frame every 3 s, labelled with a continuous label_doneness. Deliberately shoot the degraded frames too — steam, a hand, a knocked phone — because a corpus of clean frames cannot measure abstention at all. Buy the gooseneck mount first: camera shake is how this fails.
  9. ~6 hDeploy AgentCore Memory for real One service actually deployed beats six planned. Film the session-1-vs-session-3 change.
  10. ~6 hThe hot graph Perception, critic, risk, arbiter. Turn on Observability and keep the trace waterfall — it is the proof the critic is conditional rather than decorative.
  11. ~12 hVideo and submission Under three minutes, public, showing the MCP server in action. The 47-second capture is the raw material.

Cut, and say so in "What's next"

  • Multi-dish choreography. The strongest remaining differentiator and the weakest build: it needs per-dish state through state.py, server.py, policy.py and the panel, plus a perception layer that can attribute state to two pans. That is a refactor of everything, in the weeks reserved for the demo. Pitch it; do not claim it.
  • Two of the three enforcement layers, as claims. Keep all three in code. Describe deployed reality.
  • The project rename. "Not Yet" is the better name. It is not worth the churn now.
Reversing one earlier cut. The Open Source mini challenge is worth $5,000 cash plus $5,000 in credits and the rule is softer than assumed: "Create a new, additional open-source project or contribute to an existing public repository during the hackathon window, alongside a primary track submission." A contribution qualifies — it does not have to be a whole extracted library. One small upstream PR against the MCP Python SDK or the AgentCore samples, filed from friction you hit anyway, is an hour or two. Keep it.

The one sentence

What to say when a judge has thirty seconds

Every recipe app pushes you forward. This one can refuse — and advancement is gated on a recent observation, not on the model's belief.

That second clause is the part a prompted vision loop cannot claim. A prompted loop has a conversation; it has no notion of observation recency. policy.py::may_advance is twelve lines, it runs today, and it survives a skeptic. Lead with it rather than with "enforced in three places," which invites the question of how many of the three are deployed.

That risk is now retired. It was spending three weeks deepening a scaffold whose differentiating verdict had never appeared on screen. It has now appeared, been filmed, and been locked behind regression tests. The biggest remaining risk is calibration: a clear-looking frame of a genuinely ambiguous pan carries a 0.95 confidence ceiling, the clamp cannot catch a model that misreports the view, and that is where every wrong proceed this system ever gives will come from. Only a real labelled corpus and the risk-coverage sweep will find it — which makes the two AWS blockers the critical path, not the code.
